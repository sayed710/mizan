# Mizan ERP

An open, clean-room business suite inspired by the *behaviour* of full-featured ERPs — app launcher,
kanban pipelines, list/form/graph/pivot/calendar views, search panel, chatter. Written from scratch:
no third-party ERP code, assets or branding. English and Arabic (RTL).

How the reference behaviour was observed (REA browser captures) and what was a design choice is documented
in [SPEC.md](SPEC.md).

Referrals · Skills · ESG · Equity · Data Recycle · Phone · IoT · Studio · Apps · Settings (63 apps)

POS includes a Kitchen Display; users can be restricted to specific apps; company, apps and Studio changes are admin-only.

Core features on every model: kanban/list/graph/pivot/calendar/Gantt views, search panel (filters, group by, favorites,
archived), activities with a due-today counter, chatter with tracked changes, smart buttons, CSV export/import,
duplicate/archive/delete actions, multi-level grouped lists.

Accounting is double-entry (credit notes, bank reconciliation, pricelists, discounts): chart of accounts, journals, journal entries generated by invoices, payments, expenses,
POS and payroll; Profit and Loss, Balance Sheet and General Ledger reports.
Invoices can print a ZATCA phase 1 QR or an EPC/SEPA payment QR. ZATCA phase 2, Egypt ETA and UAE e-invoicing are not supported yet.

Cross-app flows: manufacturing order consumes components → finished stock; subscription → recurring invoices; POS sale → stock out;
quotation → sales order (stock out) → invoice → payment; RFQ → purchase order → receipt (stock in) → vendor bill.

## Run

```bash
npm install
npm run build
npm start          # server + app on http://localhost:8069 (login required)
```

On first start the server creates user `admin` with a random password, written to
`<database>.admin-password` (readable only by the server's user; delete it after
signing in), or set `MIZAN_ADMIN_PASSWORD`. Admins add users in **Settings**.

Environment: `PORT` (8069), `MIZAN_DB` (SQLite file, default `mizan.sqlite`),
`MIZAN_DIST` (built client folder, default `dist`), `MIZAN_SECURE_COOKIE=1` when served over HTTPS. "Reset demo" (wipe everything back to demo data) is off by default,
including a plain `npm start` and the Docker image; turn it on with `MIZAN_ALLOW_RESET=1`, or run with
`NODE_ENV=development` (then `MIZAN_ALLOW_RESET=0` switches it off again). It needs RESET typed and saves the
previous data, readable by the server's user only, to `<MIZAN_DB>.before-reset-<time>.json` first.
One server per database file: a second one refuses to start while the first is running
(after a crash, wait 30 seconds or start with `MIZAN_FORCE_TAKEOVER=1`). Every variable, and the JSON log format, is listed in
[docs/CONFIGURATION.md](docs/CONFIGURATION.md); the server refuses to start on a malformed value.

### Backups

- `npm run backup -- /path/to/dir` writes a consistent snapshot of `MIZAN_DB` (`mizan-<time>.sqlite`, made with
  SQLite `VACUUM INTO`) while the server keeps running. It holds everything: records, messages, users, sessions and API keys.
- Set `MIZAN_BACKUP_DIR` and the server takes one on start and every `MIZAN_BACKUP_HOURS` (24), keeping the newest
  `MIZAN_BACKUP_KEEP` (7). Copy that folder off the machine.
- To restore a snapshot, stop the server and put the file in place of `MIZAN_DB` (remove any `-wal`/`-shm` files next to it).
  Do not copy the live `mizan.sqlite` itself: in WAL mode recent commits may still sit in the `-wal` file.
- **Settings → Download backup** (admins) downloads the server's business data as JSON. **Restore backup** validates and migrates this JSON, then replaces business data after an admin dry run and typed RESTORE confirmation.
  Users and API keys are not included. Use the SQLite snapshot for a full restore.
- Snapshots are written owner-only (folder `0700`, files `0600`) and copied by a separate process, so a large database does not
  stall requests. `npm run backup` refuses a path that is not an existing Mizan database.

Development: `NODE_ENV=development npm start` in one terminal and `npm run dev` in another — Vite proxies `/api` to the server.
Without a server the frontend runs as a browser-only demo (data in `localStorage`).

```bash
npm test           # ORM, business-flow, sync and server tests (no build needed)
npm run coverage   # source-only coverage, files no test loads, fails below the minimums
```

### Email

Set `MIZAN_SMTP_HOST`, `MIZAN_SMTP_PORT` (587), `MIZAN_SMTP_USER`, `MIZAN_SMTP_PASS`, `MIZAN_SMTP_FROM`
(`MIZAN_SMTP_SECURE=1` for port 465). Then **Send by Email** on quotations, RFQs and invoices and **Send** on
email campaigns deliver real messages (STARTTLS when offered). Without SMTP these actions are simulated.

### Integrations

Each integration turns on when its environment variables are set; without them the buttons fall back to a local action
(simulated send, or a `wa.me` / `tel:` link).

| Integration | Environment | Used by |
|---|---|---|
| AI (Claude, `claude-opus-5-5`) | `ANTHROPIC_API_KEY` (or another Anthropic credential) | **AI Draft** in every chatter; **Digitize Document** on draft vendor bills (reads an uploaded PDF/image into vendor, reference, dates and lines) |
| WhatsApp Cloud API | `MIZAN_WHATSAPP_TOKEN`, `MIZAN_WHATSAPP_PHONE_ID` | WhatsApp button on contacts and quotations |
| SMS (Twilio) | `MIZAN_TWILIO_SID`, `MIZAN_TWILIO_TOKEN`, `MIZAN_TWILIO_FROM` | SMS Marketing campaigns |
| Carrier rate APIs (DHL, FedEx, Aramex, …) | `MIZAN_SHIPPING_TOKEN` + Rate API URL on the delivery method | **Add Shipping** on quotations |
| Marketplaces (Amazon, Noon, Shopee, TikTok, Jumia, …) | Orders feed URL on the connector, `MIZAN_MARKETPLACE_TOKEN` | **Sync Orders** (idempotent, SKU matching) |
| IoT devices | per-device token from **Generate Token** | `POST /api/iot/ingest` with `Authorization: Bearer iot_…` |

Outbound URLs configured in records must be public `https` endpoints (private network addresses are refused).

### REST API

Create a key in **Settings → API Keys**, then:

```bash
curl -H "Authorization: Bearer mzn_..." http://localhost:8069/api/v1/models
curl -H "Authorization: Bearer mzn_..." "http://localhost:8069/api/v1/crm.lead?q=desk&limit=20"
curl -H "Authorization: Bearer mzn_..." -H "Content-Type: application/json" -X POST -d '{"name":"New lead"}' http://localhost:8069/api/v1/crm.lead
```

`GET/POST /api/v1/<model>`, `GET/PATCH/DELETE /api/v1/<model>/<id>` (search with `q`, paging with `limit`/`offset`).
Send an `Idempotency-Key` header on POST to make retries safe: the same key returns the record created the first time (kept 24 hours).
Writes go through the same validation as the web client.

## Architecture

- `src/models/` — model registry (fields, filters, group-bys, view definitions, buttons) and app menus.
  The UI is generated from it: a new app is mostly a new model entry.
- `src/orm.js` — pure, immutable ORM (create/write/unlink/search, computed fields, tracking messages, grouping).
- `src/sync.js` — record-level diff/apply, so concurrent edits to different records merge on the server;
  the server validates and strips every incoming record.
- `server/index.js` — Node built-ins (`node:http`, `node:sqlite`, `node:crypto`) plus two runtime packages,
  `@anthropic-ai/sdk` (AI features, server/integrations.js) and `qrcode-generator` (src/models/qr.js): scrypt passwords,
  HttpOnly session cookies, CSRF header check, login rate limiting, static hosting.
- `src/views/` — generic Kanban, List, Graph, Pivot, Calendar, Form, plus Dashboard and Settings pages.
